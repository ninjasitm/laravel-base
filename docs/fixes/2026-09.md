## [2026-09-28] - Laravel 11–13 Model Schema Introspection

### Fixed

- Model and DbHelper table, column, index, and foreign-key discovery no longer call removed Doctrine connection methods. Native metadata retains the name/type access needed by model search, and DbHelper keeps Collection results and the column/constraint getters used by package consumers. SQLite unnamed foreign keys receive conventional synthetic names. DbHelper table and table-name caches now use separate keys; PostgreSQL table names are schema-qualified to distinguish identically named tables across schemas, while SQLite/MySQL names stay unqualified. `$catalog` remains a database/cache discriminator, not a PostgreSQL schema filter. Focused tests exercise real SQLite introspection and Laravel's PostgreSQL/MySQL builders with simulated database responses; no live PostgreSQL integration was run and no runtime dependency was added.
- **Compatibility caveat:** Adapter objects expose useful native metadata and selected legacy getters but are not Doctrine schema objects and do not implement the complete Doctrine API. SQLite does not expose original constraint names, so synthetic names may differ from names formerly reported by DBAL. The optional `$catalog`/`$dbName` arguments do not switch connections (as before); metadata is read from the active connection. PostgreSQL names now carry schema prefixes, an intentional change to avoid collisions. Cache keys include connection/database/catalog but not a mutable PostgreSQL `search_path` or schema; deployments changing those on one connection must invalidate caches before reuse. Consumers relying on Doctrine-specific methods, native object identity, or manual cache keys require separate review.

## [2026-09-22] - Cashier 15+ Test Harness Compatibility

### Fixed

- **Issue**: Package test helpers and the published API test stub called `Cashier::ignoreMigrations()`, which was removed in Cashier 15 and caused test setup to fail before application assertions ran.
  - **Root cause**: Existing optional-dependency guards checked only whether Cashier existed, not whether the legacy migration method was still available.
  - **Solution**: Guarded the legacy call with `method_exists()` so Cashier 14 retains migration suppression while Cashier 15 and newer safely skip the removed method.
  - **Files modified**: `Testing/src/TestCase.php`, `Testing/src/PackageTestCase.php`, `Api/stubs/tests/TestCase.stub.php`
  - **Status**: ✅ Fixed

### Impact

- 🔧 **Technical**: Laravel applications using Cashier 15 or newer can use the shared test harness without a missing-method fatal error.
- 🎯 **User Experience**: Downstream test suites reach their application assertions again without requiring local overrides.
- 🚨 **Breaking Changes**: None.
